# PostgreSQL 18 Backup and Migration Policy

This document defines disaster recovery, backup procedures, and schema evolution rules for the DermaScan backend.

---

## 1. Database Backup & Disaster Recovery

### 1.1 Snapshot Architecture
DermaScan uses PostgreSQL 18 as the single source of truth (ADR-0002). Backups are created using PostgreSQL's custom archive format (`-Fc`), which supports compression, metadata tagging, and multi-threaded parallel restores.

### 1.2 Creating Backups (`pg_dump`)
Run the backup script or execute directly against the production/staging container:

```bash
# Dump custom format with zstd/gzip compression and bloat exclusion
pg_dump \
    --host="${POSTGRES_HOST:-localhost}" \
    --port="${POSTGRES_PORT:-5432}" \
    --username="${POSTGRES_USER:-skincare}" \
    --format=custom \
    --compress=6 \
    --no-owner \
    --no-privileges \
    --file="dermascan_backup_$(date +%Y%m%d_%H%M%S).dump" \
    "${POSTGRES_DB:-skincare}"
```

**Recommended Backup Frequency:**
- **Daily Full Backup**: Nightly at 02:00 UTC, retained for 30 days.
- **Weekly Snapshot**: Stored in cold object storage (S3/GCS) with immutability locks (object lock/WORM), retained for 1 year.
- **WAL Archiving**: Continuous archiving for Point-In-Time-Recovery (PITR) with an RPO (Recovery Point Objective) < 5 minutes.

---

### 1.3 Restore Procedure (`pg_restore`)
To test or restore a backup into a target database:

1. Create a fresh target database:
```bash
createdb -h localhost -p 5432 -U skincare skincare_restored
```

2. Restore schema and data concurrently using 4 worker threads:
```bash
pg_restore \
    --host="${POSTGRES_HOST:-localhost}" \
    --port="${POSTGRES_PORT:-5432}" \
    --username="${POSTGRES_USER:-skincare}" \
    --dbname=skincare_restored \
    --clean \
    --if-exists \
    --no-owner \
    --no-privileges \
    --jobs=4 \
    --verbose \
    dermascan_backup_20261030_120000.dump
```

3. Post-Restore Verification:
```bash
psql -h localhost -p 5432 -U skincare -d skincare_restored -c "SELECT count(*) FROM product;"
psql -h localhost -p 5432 -U skincare -d skincare_restored -c "SELECT count(*) FROM ingredient;"
```

4. Run the integrity test suite against the restored database:
```bash
TEST_DATABASE_URL="postgresql+asyncpg://skincare:password@localhost:5432/skincare_restored" uv run pytest tests/integration/test_schema_constraints.py
```

## 2. Schema Evolution and Migration Policy

### 2.1 The Golden Rule: Additive Zero-Downtime Migrations
Migrations in DermaScan must never break running application versions during rolling deployments:
1. **Never drop or rename a column in use:** Follow the **Expand / Contract** pattern across releases:
   - **Phase 1 (Expand):** Add the new column as `NULLABLE` or with a default value. Deploy application code that writes to both columns.
   - **Phase 2 (Backfill):** Run an asynchronous queue job (`app/core/jobs.py`) to backfill data from the old column to the new column.
   - **Phase 3 (Contract):** Deploy application code reading exclusively from the new column. Once verified, release a final migration dropping the old column.
2. **Always hand-inspect autogenerated Alembic files:**
   Never commit autogenerated migrations without reviewing check constraints, foreign keys, index names, and explicit down migrations.
3. **Never modify existing committed migrations:**
   Once a migration revision has merged into `main` or deployed to staging, it is immutable. Any fixes must be implemented as a new subsequent migration.

---

### 2.2 Pre-Deployment Verification Checklist
Before opening a pull request or deploying to staging:

1. **Verify No Schema Drift:**
   ```bash
   cd backend
   uv run alembic check
   ```
   *Must exit with code 0 ("No new upgrade operations detected").*

2. **Verify Upgrade & Downgrade Reversibility:**
   ```bash
   cd backend
   uv run alembic upgrade head
   uv run alembic downgrade -1
   uv run alembic upgrade head
   ```
   *Every migration must have a working, tested `downgrade()` function.*

3. **Verify PostgreSQL Index Utilization:**
   ```bash
   uv run pytest tests/integration/test_query_plans.py
   ```
