# ADR-0003: Schema conventions
- Status: Accepted
- Date: 2026-10-16

## Decision
- **Primary keys are UUIDv7**: time-ordered (index friendly), not guessable. Generated in
  Python (`uuid.uuid7`, Python 3.14). Join tables use composite keys.
- **Enums are VARCHAR + an explicit CHECK constraint** (`enum_type` + `enum_check` in
  `app/core/orm.py`), not native PostgreSQL enums, which are painful to evolve and are not
  tracked by Alembic autogenerate.
- **Constraint names are deterministic** (naming convention on `Base.metadata`), so migrations
  can reliably alter or drop them.
- **Rules live in the database too**: barcode is exactly 13 digits, scores are 0-100, an ingredient
  rated moderate/high must have a `source_ref`, `normalized_alias` is globally unique, brand names
  are unique ignoring case. Tests in `tests/integration/test_schema_constraints.py` protect them.
- **Relationships default to `lazy="raise"`**: no hidden queries; load explicitly with `selectinload`.
- **Timestamps only where used**: `created_at`/`updated_at` on `product` (the "Recently added" shelf,
  import auditing). Other tables get them when a feature needs them.
- **Minimal columns**: a field nobody fills gives a false impression of rigor, so it is not added
  until a story needs it (e.g. alias language, ingredient function groups).

## Consequences
- Adding an enum value needs a migration that replaces its CHECK constraint (deliberate).
- Autogenerated migrations must always be read before committing.
