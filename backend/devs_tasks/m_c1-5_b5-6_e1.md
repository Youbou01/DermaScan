## 2. Detailed Technical Additions

### Added Files
* `backend/src/app/modules/scoring/engine.py` — Pure scoring math and configuration constants.
* `backend/src/app/modules/scoring/service.py` — Scoring version exposure helper.
* `backend/src/app/modules/ingredients/seed_data.csv` — Curated dataset of 24 real cosmetic ingredients.
* `backend/scripts/load_ingredient_seed.py` — Idempotent async seed loader for PostgreSQL.
* `backend/scripts/recompute_scores.py` — CLI entry point for score batch updates.
* `backend/scripts/obf_spike.py` — Open Beauty Facts dataset diagnostic spike script.
* `backend/tests/unit/test_scoring.py` — Unit test suite for the scoring engine.
* `backend/tests/unit/test_ingredient_seed.py` — CI validation test suite for ingredient security rules.

### Classes, Enums & Data Structures
* `RiskLevel` (Enum): Categorizes ingredient risk (`low`, `moderate`, `high`, `unknown`).
* `ScoreBand` (Enum): Categorizes product rating bands (`good`, `moderate`, `poor`, `insufficient_data`).
* `IngredientPositionInput` (Dataclass): Represents a labeled ingredient's risk level and 1-based index.
* `ScoreOutput` (Dataclass): Holds the final calculated score, band, coverage ratio, and algorithm version.

### Key Functions
* `calculate_score(items)`: Evaluates a sequence of ingredients, computes weighted safety averages, applies the high-risk score ceiling ($\le 49$), and verifies coverage ($\ge 50\%$).
* `get_position_weight(position)`: Applies inverse decay positioning weight where earlier components carry higher concentration impact.
* `seed_ingredients()`: Parses the CSV file synchronously and upserts records into PostgreSQL tables (`ingredient`, `ingredient_alias`, `ingredient_translation`) asynchronously.
* `validate_seed_rows(rows)`: Enforces defensibility rules ensuring any `moderate` or `high` risk record contains a non-empty `source_ref` and English rationale.

### API Endpoints
* *None* — As per task allocations, tasks C, B, and E focus exclusively on core domain data pipelines, CLI tooling, and internal analysis engines. REST controllers are managed under the Catalog module.

## 3. Step-by-Step Local Execution Guide

All commands must be executed inside the **`backend/`** directory of the repository.

### Prerequisites Setup
Ensure you have `uv` and `Docker` installed.

1. **Start PostgreSQL via Docker Compose:**
   ```bash
   docker compose up -d
   ```

2. **Apply Database Migrations:**
   ```bash
   uv run alembic upgrade head
   ```

### Running Tests & Validation Scripts

* **Run Unit Tests (Scoring & CI Seed Validation):**
  ```bash
  uv run pytest tests/unit/test_scoring.py tests/unit/test_ingredient_seed.py
  ```

* **Run the Curated Ingredient Seed Loader:**
  ```bash
  uv run python scripts/load_ingredient_seed.py
  ```

* **Run the Batch Score Recomputation CLI:**
  ```bash
  uv run python scripts/recompute_scores.py
  ```

* **Run the Open Beauty Facts Data Spike (`E1`):**
  ```bash
  uv run python scripts/obf_spike.py
  ```
